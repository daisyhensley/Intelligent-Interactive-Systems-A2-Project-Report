# Intelligent-Interactive-Systems-A2-Project-Report
Design for A2 Project Report (this is to be edited later)
Repository and README

Keep your project material in a public GitHub repository wherever possible. The README should explain:

    Project status: What you made, what works or is simulated, and what remains unfinished.
    Technology stack: The technologies and AI tools or models you used, what each does and any choices still undecided.
    Running or inspecting the work: How to run, replay or inspect what you have, including dependencies and setup where needed.
    Development record: The significant changes you made, why you made them and what you checked. Link relevant commits where available. You may group changes by feature or stage of development; screenshots of the commit history are not required.
    AI assistance: If you used AI, name the tools and explain what you asked them to help with, how you used or changed their suggestions and how you checked the result. A few relevant examples are enough; a full prompt or chat log is not required.
    Additional files: Where to find any accompanying documents or ZIP files and how to use them.

We will use the development record and relevant commit messages to understand how you approached the project. The number of commits is not a measure of quality. You do not need to repeat the README in a separate report appendix.

Keep the README brief. Short headings, bullets and setup commands are enough; it should help someone inspect your work, not become a second report. Include the information needed to use what you have, without a diary of every change. State the README’s prose word count near the top; code and setup commands do not need to be counted. There is no separate README word limit.

Never commit API keys to GitHub, even in a private repository. If a key is needed, explain how a reviewer can supply their own without including your key.
